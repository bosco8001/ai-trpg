## 單一目標

製作一份獨立手機原型，核對「配點 → 起始配套 → 角色總覽 → 戰鬥外更換配置」是否清楚可用，以及已確認的資格、停用／恢復、屬性與容量規則是否一致。像先試穿整套出發裝備，再把它接到真正的角色行囊。

原型位置為 `prototypes/phase33-starter-kit/`，另開本機 3047 原型入口，保留正式 UI、舊配裝原型、手機視覺原型與推導原型，供比較。以下是已確認的範圍與待驗證規格，不代表工程測試或使用者驗收通過。

## 展示流程

1. **配點示範**：五種族、四初階職業、六屬性基礎 8、人類單一 14 點／其他種族 12 點，初始不預先分配；沿用正式種族與職業版本、分配合計上限（人類單項 +8、其他 +6）與取整。每次調整即時計算起始配套能否啟用，紅字列出裝備／技能、原因、需求、目前判定值與差額。合法分配可保留警告繼續。
2. **配套確認**：顯示所選初始職業的武器、防具、熟練與一項主動能力，以及可用／不足狀態。返回不丟失分配；確認只建立本頁記憶體樣本，不呼叫正式創角或保存介面。
3. **角色總覽**：主畫面保留目前職業、HP／MP、配裝摘要與六格技能。資格屬性／最終屬性、完整背包與需求原因放入 Sheet。技能與裝備有生效／停用／空格文字，停用格可打開查看原因。
4. **換裝示範**：在 Sheet 選裝備、配置技能或綁定持有的魔法書；預覽屬性、容量及連帶失效，再套用。取消不改樣本、資源或配置。
5. **轉職示範**：原型提供已清楚標示為測試用的四職業切換，查看哪些配裝／技能停用或恢復。初始職業與其起始配套保持獨立，切換不重發配套、不更換永久已學或熟練來源；這不代表正式角色已開放四職業。

## 樣本與計算界線

- 原型只使用 Lv.1 記憶體樣本。種族／職業的版本、名稱、加成與倍率按正式名冊核對；新增物品／技能的門檻、加成及護甲只採討論紀錄已確認的原型樣本。
- 配點時不抽資質、資格或龍息，也不提前顯示個別結果。完成樣本後用清楚標示的固定測試結果展示資源：各種族選用其分布內的資質範例，不把它寫成正式必然結果或可選資質；不做 1% 資格生成或假保存。
- 起始配套按初始職業取得，合法項目自動配置。不符合需求的物品保留於樣本背包，已學物理技能保留於樣本技能庫；魔法書來源不當成永久學會。
- 另提供明確標示的換裝測試樣本，含上述八件樣本裝備與三項已學物理技能、書本火焰箭來源，方便跨職業與跨武器核對。測試物品／技能不偽裝成每個職業的正式起始贈送或學習命令，不加入未確認的飾品。
- 裝備需求：`floor(固有屬性 × 目前職業倍率)`，不含裝備／技能加成。先判斷各件裝備是否合法生效，再算技能資格。
- 技能需求：上述數值加生效裝備加成；再核對武器或法術來源。技能加成只進最終屬性，不支撐門檻。
- 魔法書透過技能格綁定，所綁書本須為樣本持有且符合自身裝備需求。書本是否生效依自身條件判斷，法術仍須符合其技能門檻；本批書本無屬性加成。
- 已配置項目失效時保留位置、持有與已學紀錄，停用並顯示原因；所有需求恢復後重新生效。新配置必須先符合需求；原型不新增複製物品、覆寫或隱藏自動替換。
- 樣本先依無裝備／技能的出生推導設定一次滿 HP／MP，取得與配置配套時再用已確認的容量規則：提高只加上限，降低只截超出部分，零 HP 保持零。後續預覽不修改目前資源，套用時按完整最終配置一次更新，避免中間狀態誤截資源。
- 樣本設定 Sheet 可提供受傷、耗魔與零 HP 的固定測試情境，以核對容量變化。這些是測試資料，不實作治療、回魔、傷害、瀕死或死亡命令。
- 重新整理會回到原型初始畫面；不使用正式 API、資料庫、存檔、localStorage／sessionStorage 或 LLM，不讀寫已保存角色。

## 共同 UI 規格

沿用使用者已接受的 [手機 Design System 02](../../prototypes/phase33-mobile-redesign/DESIGN_SYSTEM.md)：深色表面、較高對比按鈕、清楚黑體與數字、少量材質與刻線。採 minimalist、克制的 skeuomorphic 細節與 Swiss grid 對齊；不另做互相衝突的三套風格。

- `game-ui-ux`：畫面／Sheet 堆疊、進入與返回焦點、步驟切換回頂、草稿與已套用樣本分離，所有 HUD 與原因由同一套樣本規則更新。
- `ui-ux-pro-max`：手機資訊層級、響應式欄位與字體放大、紅字提醒及欄位關聯、可辨識停用原因。提醒不只靠顏色；即時配點不搶走焦點，提交時非法分配摘要可聚焦。
- `apple-design`：沿用字體層級與間距，按下立即回饋、清楚選取／取消結果、短且可中斷的轉場，尊重 reduced-motion／透明度／對比偏好。一般建議不得覆蓋使用者已選的視覺與紅字要求。

主畫面只留當下主要操作；一般情境長清單在 Sheet 內捲動。大字或低矮視窗若固定頂／底欄擠壓操作，改為標題、內容、操作在同一容器自然捲動，不縮字／裁字；這是可用性補修，不更改功能範圍。每個任務有一個主要 CTA；Sheet 開啟、返回、取消及快速重開都保持一致的焦點與狀態。使用者配點所致的起始配套不能啟用，按新要求使用具對比的紅字與明確文字；不沿用舊原型黃色警告來覆蓋此要求。

觸控入口至少 44×44px；文字可放大、選項可換行，四邊安全區與短螢幕操作列均納入待測。顯示與操作兼容鍵盤，不新增拖曳操作、遊戲手把輸入、音效或震動。

UI Pro Max 本次查閱 `error summary validation` 的本地 ux 資料，匹配 Forms／Accessibility 的可聚焦摘要、明確錯誤文字及欄位關聯；使用者要求的配套警告保留於畫面，分配合法時不阻擋繼續。不把設計資料查詢當成實際 UI 驗證。
