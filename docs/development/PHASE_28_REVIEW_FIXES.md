### L2：診斷查詢逾時

正式 PostgreSQL 組裝新增診斷專用連線池：最多四條連線、取得連線逾時一秒、伺服器 `statement_timeout` 兩秒、預設交易唯讀。既有連線選項保留，診斷限制於連線啟動時固定；不執行資料寫入或修改一般遊戲連線的逾時設定。

卡住的 SELECT 由 PostgreSQL 取消，沿用逐項錯誤分類為「目前無法讀取」。不是只在 JavaScript 搶先回傳，而讓原查詢繼續掛著。前端原有五秒逾時保留；取消失敗或其他網路問題仍由原有錯誤提示處理。

### L3：按鈕名稱與完成提示

- 探索頁：「重新檢查連線」，載入文字為「確認連線中……」。
- 診斷面板：「重新檢查資料」。
- 面板展開期間保留同一個 `role="status"`、`aria-live="polite"`、`aria-atomic="true"` 區域，從「正在檢查」更新為「資料健康檢查已完成……」。失敗訊息仍用 `role="alert"`。

DOM 與提示已做瀏覽器工程檢查；沒有宣稱真實 VoiceOver／其他讀屏軟體已驗證。

## 使用者可重測

依 [Phase 28 指南](PHASE_28_DATA_DIAGNOSTICS.md) 停止舊服務，啟動修正版：

1. 探索頁的連線按鈕應顯示「重新檢查連線」；系統內的診斷按鈕應顯示「重新檢查資料」。
2. 打開診斷與重新檢查，完成後應顯示「資料健康檢查已完成……」；若使用讀屏軟體，確認完成提示是否被朗讀。
3. 測試收起、再打開及中斷服務後重新檢查；仍應清除舊報告，失敗不能被說成資料損壞。
4. 重複檢查時，遊戲版本、HP／MP、回合仍應不變。
