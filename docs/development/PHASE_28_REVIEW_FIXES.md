### L2：診斷查詢逾時

正式 PostgreSQL 組裝新增診斷專用連線池：最多四條連線、取得連線逾時一秒、伺服器 `statement_timeout` 兩秒、預設交易唯讀。既有連線選項保留，診斷限制於連線啟動時固定；不執行資料寫入或修改一般遊戲連線的逾時設定。

卡住的 SELECT 由 PostgreSQL 取消，沿用逐項錯誤分類為「目前無法讀取」。不是只在 JavaScript 搶先回傳，而讓原查詢繼續掛著。前端原有五秒逾時保留；取消失敗或其他網路問題仍由原有錯誤提示處理。

## 第二次外部複查與 N1／N2 修正

使用者提供 Grok 對 `67d2d87b95eadf0ed58cef5f6868fc39cbd6da6f` 的複查報告：L1–L3 已解決，隔離 PostgreSQL 17 的 325 項測試通過，沒有阻擋手動驗收的問題；另提出 N1 環境連線選項與 N2 鍵盤焦點兩項低嚴重度問題。這是外部工程報告，報告轉交時 Phase 28 仍待使用者手動驗收。

### N1：保留 PGOPTIONS

診斷連線遵循 pg 套件的既有優先順序：網址的非空 `options` 優先；網址沒有設定或為空時，讀取 `PGOPTIONS`。選定既有選項後再追加診斷唯讀與兩秒逾時限制。因此環境設定的 `search_path`／`application_name` 會保留，網址有明確設定時亦保持原有優先順序。

不改動一般遊戲連線，不改寫環境變數。新增隔離子程序測試，避免環境設定影響其他同時執行的測試。

### N2：等待期間保持鍵盤焦點

「重新檢查資料」改用 `aria-disabled` 表示忙碌，原生按鈕保持可聚焦。同步的請求旗標與忙碌判斷會阻止重複觸發；忙碌外觀只套用此診斷面板。等待、成功與失敗都不主動搬移焦點，原有取消及舊回應排除機制保留。

本次程式範圍為 `src/server/postgres-data-diagnostics.ts`、`src/web/DataHealthPanel.tsx`、`src/web/style.css`；新增測試位於 `tests/data-diagnostics.test.ts`。文件只更新本頁、Phase 28 指南及 Implementation Plan。
