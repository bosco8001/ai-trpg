## 已確認：技能加成的容量變動

使用者對此安排回覆「合適」，明確將職業／裝備容量政策延伸至裝備技能加成的生效、移除、停用與恢復：

- 最大 HP／MP 仍依最終體質／智慧與既有公式推導。
- 上限提高時，目前值保持，不因配置技能或恢復可用而補血／補魔。
- 上限降低時，目前值只有超過新上限的部分才截低，不保留隱藏差額；再次提高上限不恢復被截掉的資源。
- HP 為 0 仍維持 0，技能加成啟停本身不救援或復活。

算法例子：假設一項技能提供體質 +1，上限由 55 增至 58，35／55 → 35／58；停用後為 35／55。若原本為 57／58，停用後截為 55／55，再恢復可用為 55／58。這些只是容量算法例子，不批准任何技能的正式屬性加成或數值。

此確認不擴大到升級或一般暫時效果，不批准技能加成參與需求判斷；技能需求仍以不含技能加成的資格數值核對。這是本次新增的使用者決策，完整範圍確認後須同步正式規格中原先未擴大至技能的界線；本輪尚未修改 Canon 或程式。

## 已確認：裝備需求的屬性來源

使用者對此方式回覆「合適」：用種族與目前職業計算後、不含任何裝備或技能加成的數值核對裝備本身的需求：`floor(固有屬性 × 目前職業倍率)`。固有屬性沿用基礎、分配與種族合併的正式規則。

裝備自身加成及其他裝備的加成均不參與任何裝備需求判斷，讓各件裝備的合法性獨立決定，避免自身支撐或裝備互相支撐。魔法書本身的裝備需求亦採此提案；具體需求數值仍待定。

技能需求維持已確認的資格數值：`floor(固有屬性 × 目前職業倍率) + 生效裝備加成`，不含技能加成。裝備提供的數值仍進入最終屬性及 HP／MP 推導；只是其加成不拿來支撐裝備門檻。

算法例子：種族與職業計算後力量為 11，一把需求力量 12、裝備後力量 +1 的劍，不能靠自己的加成裝上；即使另有力量 +1 的飾品也不能支撐該劍的裝備門檻。其力量加成若已合法生效，則可支撐技能需求。例子不批准正式物品或數值。

裝備失效處理與起始合法項目自動配置均已於下節確認；職業綁定條件仍待另訂。此確認為使用者新增決策，完整範圍確認後須同步正式規格；本輪未修改 Canon 或程式。
