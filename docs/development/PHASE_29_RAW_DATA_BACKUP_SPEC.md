## 單一目標

像在修理前影印原稿：由使用者手動下載一個 JSON 檔，完整保存伺服器目前配置角色的遊戲資料與三個存檔槽，供後續檢查與有限修復規劃使用。

保存位置依瀏覽器下載設定。這是一次原始資料匯出；一般 Load 沒有因此獲得讀取備份檔的能力。

## 備份內容與原始資料

- 目前資料只限伺服器配置的角色；三槽沿用既有槽位 1、2、3。請求不能自行指定其他角色或資料庫。
- 保留來源記錄的完整內容與必要資訊，包括角色／槽位身分、版本、來源版本與存檔時間。記憶體與 PostgreSQL 的來源表示可以不同，必須明確標示，不能偽造來源資訊。
- 目前資料內已保存的 History、敘事識別紀錄與執行協調資訊全部保留；存檔槽依其原始內容保存，不補入本來不存在的資訊。
- 備份不經過遊戲驗證器的映射或正常化，不把來源當成一般 Save 重新生成。不合法數值、缺少欄位、未知舊資料與不支援版本仍可原樣匯出，只要來源讀得到。
- PostgreSQL JSONB 已由資料庫保存為其自身表示；原始備份保留當前來源資料，不宣稱找回寫入前的排版或位元組。匯出須避免 JavaScript 數字或日期轉換造成精度損失。
- 目前資料不存在與空槽必須各自明確記錄；不得以「讀取失敗」冒充「不存在」。
- 不等待正在生成、尚未保存的 AI 文字，不補造未保存的事件或敘事。
- 不包含其他角色、整套靜態世界文件、資料庫結構、連線設定、密碼或 API key；本次範圍為配置角色的目前資料與三槽。

## 一致快照與唯讀邊界

- 四項來源必須屬於同一個一致讀取切面，不能拼接逐項、不同時間的診斷結果。
- PostgreSQL 以一致的唯讀資料庫快照取得來源；記憶體在同一同步擷取邊界複製目前資料與三槽。不得為了備份永久改動來源。
- 備份不走 `getState()` 的初始化路徑，不呼叫 Save、Load、Reset、推進回合、敘事保留／追加或結算；不改寫舊資料映射。
- 其他遊戲操作照常。介面顯示擷取時間；檔案代表擷取時刻，不保證下載完成時仍是最新狀態。
- 只防止備份操作本身重複觸發；等待、成功與失敗都不強制搬移鍵盤焦點。
- 取得連線與資料庫查詢也須有界限，逾時後清理查詢、交易與連線；不改動一般遊戲寫入的連線設定。

## 檔案格式、大小及完整性

- 單一 JSON 檔含獨立備份格式版本、資料來源、擷取時間、配置角色範圍、完整備份資料區塊與 SHA-256 校驗資訊。備份格式版本與遊戲 Save／State 版本分開。
- 固定資料區塊的編碼與校驗計算方式，確保後續工具能重現計算；實作時需明列於格式文件，不依物件鍵順序的偶然結果判定。
- 校驗值針對備份資料區塊計算，排除校驗值欄位本身。校驗通過不等於遊戲資料合法、能載入、能修復，也不是來源認證。
- 大小上限預設為 **10 MiB = 10 × 1024 × 1024 bytes**，按完整最終檔案的 UTF-8 位元組計算，包含外層資訊與校驗值；不按字數、資料區塊大小或壓縮傳輸大小判定。
- 伺服器與前端須使用一致的有效上限，並在取得與組裝過程限制資源使用；不可截斷、降級成精簡內容或提供超限檔案。
- 檔名採用帶時間的安全名稱，例如 `ai-trpg-backup-20261001-153000.json`。儲存位置由瀏覽器下載設定決定；不寫入 Git 專案或新增伺服器備份留存機制。

## 入口、成功與失敗

- 系統面板提供「下載原始資料備份」，沿用探索、戰鬥、結果與主選單入口。
- 遊戲狀態讀取失敗畫面也能獨立觸發備份；不要求診斷先得到「正常」，也不依賴一般存檔清單成功。
- 先完整取得並驗證備份外層格式、範圍、大小與校驗資訊，再發起瀏覽器下載；不以玩法合法性阻擋原始資料備份。
- 任一來源讀取失敗、超限、逾時或備份完整性驗證失敗，都不提供部分備份；錯誤提示允許手動重試，不洩露 SQL、連線資訊或原始內部錯誤。
- 完整取得內容的 30 秒等待上限涵蓋回應內容接收，不能在只收到回應標頭時提前解除。失敗、取消或離開相關介面後，舊回應不能引發意外下載。
- 成功提示：「已發起下載，請確認下載檔案。」網頁不宣稱已確認檔案寫入使用者磁碟。
- 備份不送給 LLM，不增加敘事請求或改動模型輸入政策。未來長期記憶的摘要、檢索與 token 上限另行規劃；完整備份不是完整模型提示。

## 實作後的驗收目標

以下是本階段的檢查目標，不代表使用者已逐項驗收；已執行的工程檢查見交付紀錄。

1. 正常資料、目前資料不存在與空槽都能下載完整檔案，來源表示清楚。
2. 不合法／舊版本來源仍保留原始值；目前遊戲狀態讀取失敗也不擋住備份入口。
3. 反覆備份不改動目前資料、槽位、版本、資源、回合、敘事或保存時間；空的 PostgreSQL 狀態不被初始化。
4. 同時進行遊戲操作時，備份仍來自同一快照，不混合前後資料。
5. 校驗可重算；改動資料區塊會被檢查工具識別。這只證明完整性，不宣稱修復能力。
6. 最終檔案大小邊界、慢速接收、30 秒逾時、來源讀取失敗與重試都遵守完整拒絕原則，沒有部分檔案或舊回應意外下載。
7. 鍵盤焦點、重複觸發防護、手機版面與實際下載體驗由使用者手動驗收。
